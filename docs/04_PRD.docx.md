**Как читаются приоритеты:**

* **Must** — обязательно. Без этого не запускаем.  
* **Should** — очень желательно, но можно чуть сдвинуть.  
* **Could** — хорошо бы, но спокойно откладываем.  
* **Won't** — сознательно не делаем сейчас.

**Что обязательно в MVP:**

* Быстрое создание персонажа  
* 4–6 рабочих мини-игр (Молния, Память-сетка, Переключатель, Фокус-лента \+ ещё 1–2)  
* Уровни, опыт, монеты, достижения, ежедневные квесты  
* Сбор статистики и простой экран прогресса  
* Черновые рекомендации уже с 3–5 дня  
* Привязка родителя \+ короткий понятный отчёт

**Что сознательно не делаем в первой версии:** Рейтинги, battle pass, сложный ИИ, мультиплеер, нативное приложение, сайт, B2B, сложные графики.

Есть чёткие критерии «готово» по каждой функции и отдельный список, когда MVP можно уже показывать реальным детям и родителям.

Главное правило: пока Must-функции не стабильны — никаких новых «крутых идей».

# **1\. Зачем этот документ**

Здесь зафиксировано, что входит в продукт, а что — нет. Когда будем делать через vibe-coding, этот документ будет главным источником правды. Если функции нет в PRD — её нет в продукте. Если приоритет Must — делаем в первую очередь.

# **2\. Как читаем приоритеты**

| Приоритет | Что значит |
| :---- | :---- |
| **Must** | Обязательно в первой рабочей версии. Без этого продукт не запускаем. |
| **Should** | Очень желательно в первой версии. Можно чуть сдвинуть, если упираемся в сроки. |
| **Could** | Хорошо бы иметь, но можно спокойно отложить на следующую фазу. |
| **Won't** | Не делаем. Ни сейчас, ни в ближайшие версии. Сознательный отказ. |

# **3\. Объём первой версии (MVP)**

Первая версия должна дать ребёнку полноценный игровой опыт и родителю — минимальную прозрачность. Всё остальное — потом.

## **3.1. Онбординг и персонаж**

| Функция | Приоритет | Критерий «готово» |
| :---- | :---- | :---- |
| Быстрое создание персонажа (имя \+ аватар) | **Must** | Укладывается в 40 секунд. Есть минимум 8 вариантов аватара. |
| Короткий онбординг (1–2 экрана) | **Must** | Ребёнок понимает, что делать, без длинных текстов. |
| Стартовый «талант» персонажа | **Should** | Даёт лёгкое ощущение уникальности с первой минуты. |

## **3.2. Мини-игры**

В MVP должно быть 5–6 рабочих мини-игр. Каждая привязана к конкретному навыку.

| Игра | Навык | Приоритет | Критерий «готово» |
| :---- | :---- | :---- | :---- |
| Молния | Скорость реакции | **Must** | Работает, есть 3+ уровня сложности, пишется статистика. |
| Память-сетка | Рабочая память | **Must** | Работает, сложность растёт, статистика пишется. |
| Переключатель | Когнитивная гибкость | **Must** | Правила меняются, игрок успевает адаптироваться. |
| Фокус-лента | Устойчивость внимания | **Must** | Длинная серия, видно падение точности к концу. |
| Паттерн | Логика / закономерности | **Should** | Минимум 3 типа заданий, растущая сложность. |
| Двойной поток | Разделённое внимание | **Should** | Два потока стимулов, базовая статистика. |

## **3.3. Прогрессия и мотивация**

| Функция | Приоритет | Критерий «готово» |
| :---- | :---- | :---- |
| Уровни персонажа \+ опыт | **Must** | За сессию видно рост опыта и повышение уровня. |
| Внутриигровая валюта (монеты) | **Must** | Монеты падают за игры, их можно тратить на простые вещи. |
| Достижения (базовый набор) | **Must** | Минимум 15–20 достижений. Есть редкие. |
| Ежедневные квесты | **Must** | 3 простых квеста каждый день. Награда понятна. |
| Стрики (серии дней) | **Should** | Видно текущую серию. Есть защита от срыва (1 раз). |
| Простая кастомизация персонажа | **Should** | Можно менять 2–3 элемента за монеты. |

## **3.4. Статистика и ранняя персонализация**

| Функция | Приоритет | Критерий «готово» |
| :---- | :---- | :---- |
| Сбор базовой статистики по каждой игре | **Must** | Пишутся: точность, время реакции, количество попыток. |
| Простой экран «Мой прогресс» | **Must** | Ребёнок видит рост по 2–3 навыкам. |
| Черновой профиль \+ 1–2 рекомендации (с 3–5 дня) | **Must** | Появляются автоматически. Можно проигнорировать. |
| Сравнение «я сегодня vs я неделю назад» | **Should** | Понятный визуальный рост, без сложных графиков. |

## **3.5. Родительский слой**

| Функция | Приоритет | Критерий «готово» |
| :---- | :---- | :---- |
| Привязка родителя (код / ссылка) | **Must** | Родитель видит кабинет после привязки. |
| Короткий отчёт: время \+ навыки за день/неделю | **Must** | Читается за 20–30 секунд. Без воды. |
| Лимит времени в день (ставит родитель) | **Should** | После лимита игра мягко говорит «на сегодня хватит». |
| Еженедельное сообщение-отчёт в бот | **Could** | Приходит раз в неделю. Можно отключить. |

## **3.6. Технический минимум**

| Функция | Приоритет | Критерий «готово» |
| :---- | :---- | :---- |
| Telegram Mini App \+ бот | **Must** | Открывается из бота. Работает на телефоне. |
| Сохранение прогресса | **Must** | После закрытия всё на месте. |
| Работа на iOS и Android внутри Telegram | **Must** | Проверено на реальных устройствах. |

# **4\. Что сознательно не делаем в MVP (Won't)**

* Полноценный ИИ-профиль с глубокими рекомендациями (только черновой)

* Дружеские и глобальные рейтинги

* Battle Pass и сезоны

* Сложную кастомизацию и магазин косметики

* Голосовые и анимационные излишества

* Мультиплеер и совместные игры

* Интеграцию с школами и B2B

* Нативное приложение или отдельный сайт

* Сложные графики и «научные» отчёты для родителей

Всё это можно добавить позже. Сейчас важнее сделать ядро крепким.

# **5\. Критерии, что MVP можно показывать людям**

Запускаем закрытый тест только когда выполняется всё ниже:

* Ребёнок за 7 минут понимает, что делать, и получает первое достижение

* Есть минимум 4 полностью рабочие мини-игры

* Прогресс сохраняется

* Родитель может привязаться и увидеть хотя бы время и список навыков

* Нет критических багов, из\-за которых прогресс теряется

* Тексты прошли через фильтр Документа 2 (никаких запрещённых обещаний)

# **6\. Что будет после MVP (кратко)**

Когда первая версия стабильно работает и есть первые данные:

* Углубляем персонализацию (Документ 9\)

* Добавляем 2–3 новые мини-игры

* Включаем стрики, больше достижений, простую кастомизацию

* Делаем нормальный родительский дашборд

* Только потом — рейтинги, сезоны и монетизацию

# **7\. Главное правило**

Если возникает желание добавить «ещё одну крутую штуку» до того, как Must-функции готовы и стабильны — останавливаемся. Сначала ядро, потом украшения.

**Этот документ — граница объёма. Всё, что в нём Must, должно быть сделано. Всё, что Won't — не трогаем, пока не решим иначе отдельным решением.**
