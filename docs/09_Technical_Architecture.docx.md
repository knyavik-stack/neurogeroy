# 

# **1\. Главное ограничение**

Мы не программисты. Бюджет на старте — почти ноль. Всё делаем через vibe-coding (Cursor, Claude, Lovable, Bolt и похожие инструменты). Поэтому архитектура должна быть максимально простой, понятной и опираться на бесплатные или почти бесплатные сервисы.

# **2\. Общая схема**

Продукт состоит из двух частей, которые работают вместе:

* Telegram-бот — принимает команды, шлёт уведомления, показывает квесты и отчёты родителю

* Telegram Mini App — сама игра (мини-игры, персонаж, прогресс, статистика)

Бот открывает Mini App. Прогресс хранится на сервере. Всё синхронизируется через Telegram ID пользователя.

# **3\. Рекомендуемый стек на старте**

## **Frontend (Mini App)**

* React или простой HTML \+ JavaScript (что лучше получится через vibe-coding)

* Canvas или обычные DOM-элементы для мини-игр

* Telegram Web App API (официальный) для получения данных пользователя и закрытия приложения

## **Backend**

* Node.js или Python (что удобнее писать с ИИ)

* Простой REST API или serverless-функции

* База данных: Supabase (PostgreSQL) или Firebase — оба имеют щедрый бесплатный тариф

## **Бот**

* Grammy (Node) или aiogram (Python) — оба хорошо документированы и ИИ их хорошо знает

* Webhook на том же хостинге, что и backend

## **Хостинг**

* Vercel / Cloudflare Pages / Railway / Render — бесплатные тарифы на старте

* Для базы — Supabase free tier

## **Файлы и статика**

* Картинки аватаров и иконок — в том же хостинге или Cloudflare R2 / Supabase Storage

# **4\. Что храним в базе**

Минимальный набор таблиц:

* users — Telegram ID, имя персонажа, аватар, уровень, опыт, монеты, дата регистрации

* game\_sessions — каждая партия (кто, какая игра, результат, время, точность и т.д.)

* achievements — какие достижения открыл игрок

* daily\_quests — текущие квесты игрока

* parent\_links — привязка родителя к ребёнку

* skill\_stats — агрегированная статистика по навыкам (чтобы не считать каждый раз заново)

Никаких лишних персональных данных. Имя — только то, что ребёнок сам ввёл для персонажа.

# **5\. Как работает авторизация**

Пользователь открывает бота → нажимает «Играть» → открывается Mini App. Telegram автоматически передаёт данные пользователя (ID, имя). Мы сохраняем Telegram ID как основной идентификатор. Отдельной регистрации и паролей нет.

# **6\. Ограничения free-тарифов (важно)**

На старте живём в рамках бесплатных лимитов:

* Supabase free: достаточно для нескольких тысяч активных пользователей

* Vercel / Cloudflare: хватает для MVP

* Telegram Bot API: бесплатный и без жёстких лимитов для нашего масштаба

Когда упрёмся в лимиты — это будет хороший знак (значит, появились реальные пользователи). Тогда уже будем решать, куда платить.

# **7\. Принципы разработки через vibe-coding**

* Один экран / одна функция — один понятный запрос к ИИ

* Сначала делаем работающий прототип, потом причесываем

* Всегда сохраняем код в Git (GitHub бесплатный)

* Не усложняем архитектуру «на вырост», пока не появится реальная необходимость

* Каждую мини-игру можно делать как отдельный небольшой модуль

# **8\. Безопасность и данные детей**

* Храним минимум данных

* Не просим телефон, почту, дату рождения без крайней необходимости

* Родительский доступ — только по явной привязке

* Возможность полностью удалить аккаунт и все данные

* Не передаём данные третьим лицам

# **9\. Что сознательно не делаем на старте**

* Свой сложный backend с нуля

* Микросервисы

* Сложные очереди и realtime-инфраструктуру

* Нативные приложения

* Свой сервер вместо готовых PaaS

# **10\. Главный принцип**

Техника должна служить продукту, а не наоборот. Если можно сделать проще и дешевле — делаем проще и дешевле. Красивая архитектура появится тогда, когда появится продукт, который люди реально используют.

**Мы строим так, чтобы два не-программиста с помощью ИИ могли довести MVP до реальных пользователей.**
